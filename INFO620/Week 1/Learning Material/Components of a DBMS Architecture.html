Week 1 Database Concepts, Architecture, and Components

Components of a DBMS Architecture

A DBMS is composed of multiple interacting components that manage data efficiently. Understanding these components is essential for analyzing system behavior, performance, and administrative responsibilities. According to Khurana (2024), there are five major DBMS architectural components.

The query processor translates high-level SQL queries into low-level instructions. Its functions include the following:

  • Parsing
  • Query optimization
  • Execution planning

A poorly optimized query processor can slow performance dramatically, especially in enterprise systems, where thousands of queries run concurrently.

The storage manager controls the interaction between logical structures (tables, indexes) and physical storage (blocks, pages, files). Its responsibilities include the following:

  • File management
  • Buffer management
  • Data access methods

The transaction manager enforces the ACID properties (atomicity, consistency, isolation, and durability). This allows multiple users to interact with the database safely, without interfering with each other’s operations.

The metadata catalog stores definitions of tables, indexes, schemas, constraints, relationships, and permissions. This catalog is essential for query validation and optimization.

The concurrency control and recovery subsystems prevent conflicts and ensure that databases can recover from crash failures or incomplete transactions.

Understanding the roles of these components will help you analyze system architecture and identify potential performance bottlenecks.
