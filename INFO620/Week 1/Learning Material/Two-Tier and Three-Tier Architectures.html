Week 1 Database Concepts, Architecture, and Components

Two-Tier and Three-Tier Architectures

Enterprise systems rely on robust architectural designs that allow users to access data efficiently and securely. The two most common architectural patterns presented in this course are the two-tier and three-tier models.

Two-Tier Architecture

In a two-tier system, an application communicates directly with the database server. This model is common in small or mid-sized applications, but it presents limitations in scalability and security. The application layer must handle the business logic, communication, and user interface responsibilities.

Three-Tier Architecture

A three-tier system introduces a middle layer, such as an application server, between the user interface and the database. This approach provides significant advantages:

  • Scalability: Middle-tier load balancing supports more users.
  • Security: The database is not directly exposed to clients.
  • Maintainability: Business logic is centralized.
  • Performance: Application servers cache, batch, optimize, and coordinate requests.

Three-tier architectures are used in enterprise web systems, cloud-based services, and distributed platforms. Most modern DBMS deployments rely on n-tier (multitier) extensions of this model, especially in cloud environments, where microservices are common.
