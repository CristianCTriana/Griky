The relational model, introduced by Edgar Codd, provides a mathematically sound structure for organizing and querying data. As Khurana (2024) describes, the model is based on a set of well-defined constructs: relations, attributes, tuples, domains, schemas, and keys. These constructs ensure that databases maintain consistency regardless of the complexity or size of data.

A relation is a table-like structure composed of rows and columns:

  • Attributes represent column names.
  • Tuples are rows representing individual records.
  • Domains specify the allowable values for each attribute.

For example, the attributes for a Customer relation might look like this:
(CustomerID, FirstName, LastName, Email, Phone).

Each attribute has a domain, such as Email, that requires a valid email pattern.

Keys ensure unique identification of tuples as follows:

  • Primary key (PK): Uniquely identifies tuples
  • Candidate keys: Alternative unique identifiers
  • Foreign keys (FK): Establish referential integrity between relations
  • Composite keys: Keys formed from multiple attributes

Keys are critical in preventing duplication and maintaining data consistency.

A relational schema represents the structure of relations and their relationships. For instance:

  • Customer(CustomerID, Name, Email)
  • Order(OrderID, CustomerID, Date)

This schema directly supports normalization, which you will learn about in Week 4.
