Week 3 Relational Theory, Constraints, and Relational Algebra

Integrity Constraints and Anomalies

Relational databases rely on constraints to ensure data accuracy and prevent inconsistencies. Without properly enforced constraints, data becomes vulnerable to:

Corruption Redundancy Anomalies

Khurana (2024) identifies several categories:

  1. Domain constraints
    Specify valid attribute values.
    Example: Salary must be a positive number.
  2. Entity integrity constraints
    Ensure primary keys cannot be null.
  3. Referential integrity constraints
    Require that foreign key values match existing primary key values.
    For example, if an Order references a CustomerID that does not exist in Customer, this violates referential integrity.
  4. Key Constraints
    Prevent duplicate primary key values.
  5. Semantic (Business) Constraints
    Example: An employee’s end date must come after the start date.

These constraints ensure relational designs remain meaningful and valid.

Poorly structured schemas can cause three types of anomalies:

  1. Insertion anomaly
    Occurs when certain attributes cannot be inserted into the database without inserting other unnecessary data.
    Example: You cannot add a new product unless a sale is recorded.
  2. Update anomaly
    Requires modifying multiple tuples to update a single fact.
    Example: You must change a customer’s address across several order records.
  3. Deletion Anomaly
    Deleting one tuple unintentionally deletes valuable data.
    Example: Deleting the last order for a supplier removes all information about that supplier.

These issues set the stage for Week 4’s focus on normalization.

Conceptual Example

A single “OrderDetails” table containing Customers, Orders, and Products results in severe redundancy and anomalies. Decomposing this into separate, normalized relations prevents inconsistencies.
