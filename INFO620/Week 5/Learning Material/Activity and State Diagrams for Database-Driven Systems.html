Activity and State Diagrams for Database-Driven Systems

Activity and state diagrams capture process flows and state transitions that are crucial for understanding system logic and database triggers.

Activity Diagrams

Activity diagrams resemble flowcharts but emphasize concurrency and decision points. They have the following key elements:

  • Actions: Perform query, update record
  • Decision nodes: Payment approved?
  • Fork/Join nodes: Parallel processing
  • Swimlanes: Partition actions by role

Consider the following example workflow for Order Fulfillment:

  1. ReceiveOrder
  2. ValidateInventory
  3. ProcessPayment
  4. UpdateDatabase
  5. SendConfirmation

Relationship to Databases

Activity diagrams reveal when

  • data is created,
  • data is updated,
  • data is validated, and
  • data is archived.

They help identify constraints and triggers required in the schema.

State Diagrams

State diagrams track lifecycle changes of entities.

Consider the following example for Order Entity:

  • States: New → Paid → Packed → Shipped → Delivered
  • Events: PaymentReceived, PackageReady
  • Transitions: DB updates moving the order through states

Practical Example

A database designer may create a trigger as follows:
“When Order moves from ‘Paid’ to ‘Packed’, decrease Product stock.”

Thus, state transitions may result in the following:

  • SQL updates
  • Trigger activation
  • Logging events
  • Audit trail entries
