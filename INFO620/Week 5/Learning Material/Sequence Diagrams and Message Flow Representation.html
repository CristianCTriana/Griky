Week 5 UML Behavioral Modeling

Sequence Diagrams and Message Flow Representation

Sequence diagrams show how objects or system components interact over time. They are essential for illustrating how a database participates in workflows.

Elements of a sequence diagram include the following:

  • Lifelines: Participants such as User Interface, Controller, DBMS
  • Activation bars: Time spent processing
  • Messages: Queries, commands, responses
  • Return messages: Acknowledgments or data objects

Sequence diagrams emphasize temporal ordering.

Example: Login Authentication Process

Consider this example:

Participants: User → Web App → Authentication Service → Database

Messages:

  1. User submits credentials
  2. Web App sends request to Auth Service
  3. Auth Service queries DB:
    SELECT * FROM Users WHERE Username = ?
  4. DB returns result
  5. Auth Service validates password
  6. Web App returns success/failure

Relevance to Database Design

These diagrams reveal the following:

  • Required queries and their frequencies
  • Simultaneous operations (impacting concurrency control)
  • Potential bottlenecks in request flow
  • Security checkpoints

Understanding message flow is essential for tuning indexes, optimizing SQL, and planning access control.

Mapping ER/EER Models to Sequence Behavior

Behavioral diagrams complement static ER structures by answering the following questions:

  • Which data are accessed?
  • In what order?
  • By whom?
  • With what conditions?
  • Under what constraints?

This interplay ensures the final schema supports the required system functionality.
