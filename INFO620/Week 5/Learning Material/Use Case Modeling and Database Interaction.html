UML Behavioral Modeling

Use Case Modeling and Database Interaction

Use case diagrams provide a high-level view of system functionality from the perspective of external actors. They emphasize what a system must do, not how it does it. This makes use cases foundational for understanding database requirements.

Identifying Actors

Actors represent the following:

  • Users (e.g., Customer, Employee, Manager)
  • External systems (e.g., Payment Gateway, HR System)
  • Devices (e.g., Scanner, Mobile App)

Actors must be distinguished by their goals and interactions with the system.

Use Case Elements

A standard use case diagram includes the following:

  • Actors
  • Use cases (goals or tasks)
  • Associations (lines showing interactions)
  • Includes and Extends relationships
  • System boundary

Example: Online Retail Database System

  • Actors: Customer, Inventory System
  • Use cases: Place Order, Update Inventory, Track Order

“Place Order” may include the following: Validate Payment, Notify Customer.

Use Cases and Database Requirements

Use cases reveal the queries, updates, and transactions that a database must support. For example:

  • Use case: Customer places an order
  • Database implications:
    • Insert into Order table
    • Insert multiple rows into OrderLine
    • Update Product stock
    • Validate CustomerID exists

These connections set the stage for Week 6, focusing on database security, and Week 7, focusing on data warehousing.
