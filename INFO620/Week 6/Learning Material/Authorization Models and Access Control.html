Week 6 Database Security and Authorization

Authorization Models and Access Control

An authorization specifies the permissions granted to individuals for data handling. Effective authorization mechanisms safeguard against unauthorized access, modification, or deletion of information. Khurana (2024) delineates three primary authorization models employed in database systems:

DAC grants privileges based on user identity and allows users to delegate permissions. DAC is

  • Common in relational systems such as MySQL, PostgreSQL, and Oracle
  • Flexible but vulnerable to privilege proliferation

Example:
A table owner may grant SELECT privileges to a colleague.

MAC assigns security labels to data and users, enforcing strict rules that users cannot override. MAC

  • Is used in government and military systems
  • Uses classification levels: Confidential, Secret, and Top Secret
  • Enforces “no read up, no write down” policies

MAC ensures enforced separation between security levels.

RBAC assigns permissions to roles, and users gain privileges by belonging to roles. RBAC

  • Is scalable and manageable;
  • Supports least-privilege principles; and
  • Is common in enterprise systems.

Consider this example:

  • Role: “Database Auditor”
  • Permissions: SELECT on logs, no UPDATE privileges
  • Users added to the role inherit privileges

SQL grants privileges such as the following:

SELECT INSERT UPDATE DELETE EXECUTE (stored procedures) REFERENCES (FK constraints)

These privileges can be applied to the following:

  • Individual tables
  • Specific columns
  • Views
  • Schemas
