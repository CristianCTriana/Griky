Week 1 Project Management and Project Work

Project Life Cycle

The project life cycle—which includes the initiation, planning, execution, monitoring and controlling, and closing phases of a project—are foundational principles of project management. Each phase of the project life cycle plays a specific role in promoting project success.

During the initiation phase, the project is defined, key stakeholders are identified, benefits are clarified, and the project’s “why” is clearly explained to the team, including its significance (Project Management Institute [PMI], 2025).

The planning phase is then used to transform the project’s initial purpose into a structured path by developing the scope, schedule, cost, quality, resources, risk, and other performance domains critical to meeting the project’s outcomes.

The execution phase translates the work defined in the project plan into actionable items the project team needs to complete, details the resources they need to coordinate, and identifies the stakeholders they need to interact with to deliver the project in line with expected deliverables.

The monitoring and controlling phase ensures the project’s progress aligns with expectations and performance baselines by tracking progress and deviations and managing project risks.

Finally, the closing phase ensures acceptable deliverables; contracts reflect agreements; lessons learned are documented and used to improve the next project plan (PMI, 2025).

Selecting an ideal project life cycle model—predictive, iterative, or agile—requires determining the level of uncertainty, the pace of change, and stakeholder engagement needs.

Predictive

Predictive life cycles are often used when the project requirements are stable and well comprehended, allowing for more detailed upfront planning and controlled execution (PMI 2021).

Iterative

An iterative model is better suited when the project team can refine the project solution using frequent cycles of planning and development.

Agile

However, when the project has high uncertainty or is riddled with rapidly changing needs, the agile life cycle model offers more flexibility through short iterations, ongoing customer collaboration, and incremental value delivery (PMI, 2025).

The PMBOK® Guide emphasizes tailoring, encouraging project managers to choose a life cycle model based on context rather than defaulting to just one model for all projects. When deciding which project life cycle model to use, project managers should also evaluate key factors such as:

  • The project requirements
  • Risk exposure
  • Organizational culture
  • Stakeholder availability (PMI, 2025)

For example, a predictive model is more appropriate for compliance-driven projects with precise documentation, while an agile model is better suited to innovation-oriented projects with changing requirements. The goal is to align the project life cycle with the appropriate project attributes so that project managers can enhance the project’s efficiency and adaptability to further validate stakeholder satisfaction.
