Week 6 Database Security and Authorization

Protecting Against SQL Injection

Even strong preventive measures are insufficient without continuous monitoring. Enterprise databases must implement auditing, logging, and intrusion detection.

Database Auditing

Auditing tracks the following information:

  • Login attempts
  • Data modifications
  • Permissions changes
  • Access to sensitive tables

Audit Trail Example

When a user updates a salary field, the audit log records the following:

  • Who made the change
  • When it occurred
  • Old and new values

Audit logs support compliance, forensic analysis, and anomaly detection.

Monitoring and Alerts

Monitoring tools evaluate the following:

  • Query performance
  • Suspicious behavior patterns
  • Failed login spikes
  • Unusual data access volumes

Real-time alerts notify administrators of high-risk events.

Intrusion Detection and Prevention

Database intrusion detection systems (DIDS) include the following elements:

  1. Signature-based detection: Matches known attack signatures.
  2. Anomaly-based detection: Detects behavior outside normal patterns.
  3. Preventive controls: Automatically block or throttle suspicious sessions.

The Human Factor: Security Policies

Many breaches result from human error, not technological flaws.
Therefore, security policies should include the following:

  • Acceptable use standards
  • Access request procedures
  • Password policies
  • Data handling guidelines
  • Regular audits of privileges
  • Mandatory security training
Putting It All Together

A secure database system must integrate the following layers:

Strong authentication Well-designed authorization Encryption Network security Auditing Monitoring User training

This layered approach is called defense-in-depth.
